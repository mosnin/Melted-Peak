# Retrospective -- Summary

Post-completion analysis that extracts lessons from work and feeds them back into Melted Peak. Every resolved issue makes the system smarter -- updates regression checklists, refines skills, tunes context profiles, and tracks effectiveness metrics.

## When to Use
- After resolving an issue (especially hard ones)
- After completing a feature
- User says `/retro`
- After the three-strike rule was invoked

## Key Steps
1. **Gather evidence**: Read issue, change plan, deltas, regression checklist
2. **Analyze**: What went well, what went wrong, what was surprising
3. **Feed back**: Update regression checklist, skills, context profiles, architecture decisions
4. **Log metrics**: Attempts, sessions, scope drift, regressions, skills used
5. **Check patterns**: Read last 5 retros, identify systemic issues

## Safety Rules
- Never auto-modify protocols (require user confirmation)
- One improvement at a time
- Log all system modifications as `[system-self-improvement]`
- Validate improvements on next use
